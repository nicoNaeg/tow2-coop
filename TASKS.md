## End goal: no commands, host and join from the game's menu (owner's target, 2026-11-17)

Not started; after the two-PC test. A player installs by double-click and never types a command, role or Steam ID:

- One install that can host or join; the role is picked in the game (a joined session keeps saving off only while it
  lasts, so the same install plays solo normally).
- In the main menu the host picks whether to host its world and who can join: private, friends, public.
- The joining player sees a list of joinable games (friends' and public ones) and joins from it; Steam "Join game" from
  the friends list too.
- Likely route: Steam lobbies (`ISteamMatchmaking` of the game's own `steam_api64.dll`: lobby type = private / friends /
  public, lobby data = mod version, host name, map) for the list, the existing Steam link and hand-over for the join,
  and a small overlay drawn by the mod for the menu (the game's own notification widget only shows string-table text).
  Unknowns to probe first: whether lobbies work under the game's app id, and drawing an overlay on its D3D12 swap chain.

## End goal 2: play the whole game together, each with their own character (owner's target, 2026-11-17)

Status (2026-11-18): rows 9a-9e. Own items, money and level (9a), party XP (9b) and own look (9c) pass on one PC
(runs 70-81); trading (9d) mirrors container stores, but players can't store into world containers in the game's own
screens (probe 78): a way to give items is still to be chosen. Not yet tried across two PCs. Wanted:

- The friend joins with nothing and builds their own character: their own weapons, items, money and progression,
  picked up in the shared world; the two players can trade items.
- Play from the start of a new game together.
- Likely route: the mod keeps the friend's character (inventory with each item's state, equipment, ammo, money, XP,
  level, skills, perks, health) in its own file on the friend's PC, per host campaign, and restores it on the loaded
  pawn after every hand-over (the host's save stays the world). First join: an empty inventory. Trading: a give/drop
  message that removes the item on one side and adds it on the other. The friend's own look (from their own save or the
  character creator) and the stand-ins showing it come with it.
- Known API (probe 56): `InventoryComponent.GiveItemToActor / RemoveItemFromActor / GetItemCountOnActor`,
  `AddCurrency / RemoveCurrency`, `EquipmentComponent.EquipArmor_BP`. Unknowns: listing a character's items and each
  item's own state (weapon mods, ammo in the magazine, durability), setting XP, skills and perks.
